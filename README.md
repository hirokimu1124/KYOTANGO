# 画面モニター（遠隔授業用）

生徒（Chromebook）の画面を先生が一覧でリアルタイムに見るためのWebアプリ。
手が止まっている生徒を自動で色分けし、生徒は「🙋 困っています」ボタンで先生に知らせられる。

## ファイル
- `index.html` … 生徒用（先生から送られたURLで開き、名前を入れて画面共有）
- `teacher.html` … 先生用（一覧・拡大・メッセージ送信）。先生用URL（`?co=…&k=…&t=…`）で開くと副担当として参加
- `gas/Code.gs`・`gas/appsscript.json` … スプレッドシート記録用の Apps Script（記録・入退室まとめ・自動更新）
- `publish.bat`・`publish.sh` … 公開スクリプト（Windows はダブルクリック、Mac は ./publish.sh）

## 仕組み
- WebRTC（PeerJS 1.5.4）で生徒→先生へ画面を直接ライブ配信。遅延は1秒未満。
- 接続の仲介はPeerJSの無料公開サーバー（0.peerjs.com）。映像はサーバーに保存されず、録画もしない。
- 一覧表示中は軽量画質（横640px・約4fps・250kbps）。タイルをクリックして拡大した生徒だけ高画質（約10fps・2Mbps）に切り替わる。
  40人で先生側の受信はおよそ10Mbps。
- 先生側で1秒ごとに各画面の変化を調べ、変化がない時間で色分けする（初期値：2分で黄、5分で赤）。
  画面下端（Chromebookの時計・シェルフ）は判定から除外。

## 授業での使い方
1. 先生：`teacher.html` を開き「生徒用URLをコピー」→ Zoomのチャットで送る
2. 生徒：URLを開き、名前を入力 →「画面共有をはじめる」→「画面全体」を選んで共有
3. 生徒はそのタブを閉じずに、課題のタブへ切り替えて作業
4. 先生：要対応順に並ぶので、上から確認。クリックで拡大＋メッセージのやり取り

## メッセージ機能
- 生徒→先生：生徒ページの「💬 先生とのメッセージ」欄から送信。先生側はタイルに「💬 未読数」が出て音が鳴り、一覧の上位に並ぶ。
- 先生→生徒：タイルをクリックした拡大画面の右側で、その生徒との履歴を見ながら返信（定型文ボタンあり）。
- 先生→全員：上部の「📢 全員に送信」で、つながっている生徒全員に一斉送信。
- 先生側の履歴は先生のブラウザに保存（クラスコードごと。「コードを変更」で消去）。生徒側の履歴はタブを閉じると消える（共用端末対策）。サーバーには残らない。
- 相手とつながっていないときは送信できない（その旨を表示）。

### メッセージを見逃さないしくみ
- 生徒：「📌 先生からのメッセージを常に手前に表示する」を押すと、ほかのタブやアプリの上にずっと出る小窓が開く（Chrome の Document Picture-in-Picture）。先生のメッセージが届くと小窓が光って本文を表示。小窓から返信と🙋もできる。**ブラウザの制約で、生徒自身がボタンを押さないと開かない**ので、授業の最初に押してもらう。
- 生徒用ページを見ているときは、画面中央に「わかりました」を押すまで消えないポップアップが出る。
- 小窓を開いていないときは、通知を許可していれば Chromebook の通知も出る。
- 先生：「🔔 通知」にチェックすると、このページを見ていないとき（Zoom など）に生徒のメッセージと🙋をパソコンの通知で知らせる。通知を押すとその生徒の拡大画面が開く。

## 学級ごとにURLを固定する
- 先生用ページ上部の「学級」で切り替える。「⚙ 学級」で追加・名前変更・削除（最大30学級）。
- 学級ごとに **クラスコード・生徒用URL・先生用URL が固定**。生徒には毎回同じ生徒用URL（ブックマーク可）を使ってもらえる。
- 「⚙ 学級」→「ブックマーク用URL」（`teacher.html#c=コード`）を開くと、その学級の先生用ページが直接開く。
- メッセージ履歴・「外した先生」の一覧・先生用URLの合言葉は学級ごとに別。
- URLが漏れたときは、その学級を表示して「URLを作り直す」（その学級だけ新しいURLになる）。
- URLは先生のブラウザに保存された鍵から作られるので、**いつも同じパソコンの同じブラウザ**で開くこと（別のブラウザやサイトデータ削除で変わる）。
- 以前の1学級だけの設定は「学級1」として引き継がれ、配布済みのURLはそのまま使える。
- スプレッドシート記録のクラスコード欄は「学級名／コード」になる。

## 複数の先生で見る（主担当1名＋副担当最大4名）
1. 主担当：「👥 先生」→「先生用URLをコピー」→ 一緒に見る先生に送る（最初に1回だけ。**生徒には絶対に送らない**）
2. 副担当：先生用URLを開いて表示名を入れるだけで参加（承認の操作は不要）
3. **主担当がページを開くと**、待っていた副担当と生徒が自動で始まる。主担当が入るまでは「主担当の先生の入室を待っています」と表示される

- 主担当・副担当とも画面とボタンは同じ。主担当だけの操作（コードを変更・先生用URLを作り直す・記録設定・先生を外す）は、副担当の画面では灰色で押せない。
- 副担当も「生徒用URLをコピー」「📢 全員に送信」「👥 先生（参加中の先生一覧）」を使える。
- 先生用URLには先生専用の合言葉（`t`）が入っている。漏れたときは主担当が「先生用URLを作り直す」→ 古いURLは使えなくなり、参加中の副担当もいったん外れる（新しいURLを送り直す）。
- 特定の先生だけ外すときは「👥 先生」→「外す」（先生用URLを作り直すまで、その先生は再参加できない）。
- 生徒のメッセージは全先生に届く。誰かが返信すると、ほかの先生の画面にも「先生（田中）」のように表示される。後から入った先生にもそれまでのやり取りが共有される。
- 生徒は副担当にも本人確認（署名の検証）をしてから画面を送る。副担当の鍵の指紋は、主担当から本人確認済みの接続で届く。
- スプレッドシート記録は主担当のパソコンからだけ行う（副担当の返信も主担当経由で記録される）。
- 生徒側の送信量は先生の人数分になる（一覧用の軽い画質で 1人あたり約0.25Mbps × 先生の数）。

## 通信量と省データ設定
| 状態 | 画質 | 1本あたりの上限 |
|---|---|---|
| 一覧（通常） | 横640px・毎秒4コマ | 0.25Mbps |
| 一覧（省データ） | 横640px・毎秒2コマ | 0.15Mbps |
| 拡大表示中の生徒 | 最大1920px・毎秒10コマ | 2Mbps |

- 生徒の送信 ＝ 上限 × 先生の人数（先生5人・通常で最大1.25Mbps）。Zoomの送信が別にかかる。
- 先生の受信 ＝ 上限 × 生徒数（40人・通常で最大10Mbps、省データで最大6Mbps）。先生ごとにかかる。
- 画面が止まっているときはごくわずか（実測 約0.02Mbps）。ダミー画面での実測は、通常 約150kbps／省データ 約120kbps／拡大 約320kbps（実際の画面では変わる）。
- 「省データ」は先生ごとの設定（自分に届く一覧の映像だけが軽くなる）。設定は次回も保持。
- 先生画面の「📶 受信」に、受信量・累計・1人平均と、中継サーバー経由の生徒数（直接つながれない生徒）を表示。拡大画面にはその生徒の通信量を表示。
- 生徒画面に「📶 送信」（先生何人分か・累計）を表示。

## スプレッドシート記録の準備（初回だけ・約5分）
先生用ページから、やり取りをGoogleスプレッドシートへ自動で追記できる。
記録されるのは「生徒→先生」「先生→生徒」「先生→全員」「🙋ボタン」「入退室（IPアドレスつき）」。列は 日時／クラスコード／生徒名／送信者／内容／生徒ID／メッセージID／IPアドレス。

### 入退室の記録
- 先生側も記録する。生徒名の欄が「先生（名前・主担当）」「先生（名前・副担当）」の行。
  - 主担当：先生用ページを開いて仲介サーバーにつながった時点で入室、閉じる・学級を切り替える時点で退室（IPは STUN で調べたインターネット側のアドレス。分からなければ最初の接続から補い、30秒たっても分からなければ「不明」）。
  - 副担当：主担当が参加を承認した時点で入室、接続が切れた・外された・先生用URLを作り直した時点で退室。
  - 先生用URLが古い・正しくない、外した先生、人数上限で参加を断った場合は「参加を拒否：理由（IP …）」を記録（1回の授業で20件まで）。
- 送信者が「入退室」の行。内容の例：`入室（IP 203.0.113.5・直接）`、`退室（IP 203.0.113.5・滞在 42分）`、`再接続（IP …）`、`記録終了：先生のページを閉じた（…）`。
- IPアドレスは、生徒との接続で実際に使われている経路（WebRTC の getStats）から取り、見えない場合は生徒側が知らせてきたインターネット側のアドレス（SDP の srflx 候補）を使う。分からなければ「不明」。
- 学校から参加する場合、同じ学校の生徒は**全員同じIP**（学校の回線の出口）になることが多い。家庭や学校外からの参加を見分ける目安として使う。
- 退室は、生徒のページが閉じた・通信が切れたことを先生側が検知した時点で記録する（回線が急に切れた場合は数十秒遅れることがある）。
- 先生のページを閉じた後の退室は分からないため、閉じた時点で接続中の生徒に「記録終了」を記録する（次にページを開いたときに送られる。日時列は閉じた時刻）。
- IPアドレスは個人に関する情報として扱い、生徒・保護者への事前説明に「接続元のIPアドレスを記録する」ことを含める。
- 以前の `Code.gs` のままでも、IPアドレスは内容の欄に入る。IPアドレス列に分けて残すには、新しい `Code.gs` に貼り替えて新バージョンでデプロイし直す（既存のシートには見出しが自動で足される）。

1. Googleドライブで新しいスプレッドシートを作る（名前例：画面モニター記録）
2. メニュー「拡張機能」→「Apps Script」を開き、最初からあるコードを消して `gas/Code.gs` の中身を貼り付けて保存
3. 左の「プロジェクトの設定」（歯車）で「「appsscript.json」マニフェスト ファイルをエディタで表示する」にチェック →
   エディタに出た `appsscript.json` の中身を `gas/appsscript.json` に置き換えて保存（自動更新に必要な権限が入っている）
4. https://script.google.com/home/usersettings を開き「Google Apps Script API」を**オン**（自動更新に必要。1回だけ）
5. 上部の関数選択で `setup` を選び「実行」→ 権限の確認が出たら自分のアカウントで許可
   （「このアプリは確認されていません」と出たら「詳細」→「（安全ではないページ）に移動」）
6. 下の実行ログに出る **合言葉** を控える（あとでスプレッドシートのメニュー「画面モニター」→「合言葉を表示」でも見られる）
7. 右上「デプロイ」→「新しいデプロイ」→ 歯車で「ウェブアプリ」を選ぶ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   →「デプロイ」→ 表示された **ウェブアプリURL**（…/exec）をコピー
8. 先生用ページの「📝 記録設定」に URL と合言葉を入れ「接続テスト」→ 成功したら「保存して閉じる」

- ヘッダーの「記録：✅ 保存中」が出ていれば記録されている。通信が切れても送信待ちとしてためておき、つながり次第自動で送る（重複はしない）。
- URLと合言葉は先生のブラウザにだけ保存される（公開されるファイルには含まれない）。生徒のページからは記録しない。
- `setup` を実行すると次の2つが自動で動く（スプレッドシートのメニュー「画面モニター」→「自動化の状態を見る」で確認できる）。
  - **入退室まとめ**：1時間ごとに「ログ」から「入退室まとめ」シートを作り直す（日付・学級・人ごとに、最初の入室／最後の退室／滞在合計／入室回数／再接続／IPアドレス／回線／備考）。「回線」は、その日その学級の生徒でいちばん多いIP（学校の回線など）と同じか「別の回線」か。今すぐ作るときはメニュー「入退室まとめを今すぐ作る」。
  - **自動更新**：毎日午前3時ごろ、GitHub の `gas/Code.gs` と `gas/appsscript.json` の最新版を取り込み、新しい版を作ってウェブアプリを切り替える（URL・合言葉は変わらない）。すぐに確かめるときはメニュー「最新版を確認して更新する」。止めるときは「自動更新を止める／再開する」。
  - 自動更新が失敗し始めたときは、Google から「スクリプトのエラー」の通知メールが届く。多くは手順4（Apps Script API）か手順3（appsscript.json）が原因。
  - 自動更新は、このリポジトリ（GitHub の hirokimu1124/KYOTANGO の main）にあるコードを、記録用スプレッドシートの持ち主の権限で動かすことになる。リポジトリに書き込めるアカウントは自分だけにしておく。
  - 権限（appsscript.json の oauthScopes）が増える更新のあとは、エディタで `setup` をもう一度実行して許可し直す。
- **以前の版から移るとき（1回だけ）**：手順2〜5を行う（コードと appsscript.json を貼り替え、Apps Script API をオンにして `setup` を実行）。`setup` が最新版のウェブアプリへの切り替えまで行うので、デプロイの操作はいらない。
- 生徒の発言を保存するので、学校の個人情報の取り扱いルールを確認しておくこと。

## セキュリティ対策
- **先生のなりすまし防止**：先生用ページは初回に署名用の鍵（ECDSA P-256）を作り、秘密鍵を取り出し不可の形でそのブラウザ（IndexedDB）に保存する。
  生徒用URLの `k` は公開鍵の指紋。生徒ページは接続のたびに乱数を送り、先生の署名を確かめてから名前・画面を送る。
  URLやクラスコードを知っていても、先生のブラウザがなければ画面は受け取れない。
- **名前を仲介サーバーに渡さない**：名前などは本人確認後、暗号化された直接接続で送る。
- **改ざん対策**：PeerJSはSRI（integrity属性）付きで読み込む。
- **いたずら対策**：生徒1人あたりメッセージは30秒に5件、🙋は1分に10回まで。接続は最大80人。生徒ページ側も2秒に1件まで。
- 先生の鍵はそのブラウザ専用。**別のパソコン・別のブラウザ・シークレットウィンドウで先生用ページを開くと生徒用URLが変わる**（URLを送り直す）。
  ブラウザのサイトデータを消した場合も同様。
- 第三者が授業前に先生の接続IDを先に取ると、先生のページが「使用中」になる（画面は漏れない）。続く場合は「コードを変更」。

## 公開（更新）の手順

- **Windows**：作業フォルダの `publish.bat` をダブルクリック。**Mac**：ターミナルで `./publish.sh`（説明をつけるなら `./publish.sh "直した内容"`）。
- やること：GitHub の最新を確認 → 変更したファイルの版（`teacher.html` の `APP_VERSION`、`gas/Code.gs` の `SCRIPT_VERSION`）を今の日時に書き換えてコミット → GitHub 側の新しい変更（Claude が直接反映した分など）を取り込む → GitHub に送る。
- 対象は、すでに公開しているファイルだけ。新しいファイルは一覧に表示するだけで、自動では公開しない（作業フォルダの関係ないファイルを公開してしまわないため）。
- 公開用の管理情報が作業フォルダの外（`~/.kyotango-deploy.git`）にあれば自動でそれを使う（作業フォルダにあるバックアップ用の Git は使わない）。別の場所なら環境変数 `KYOTANGO_GIT_DIR` で指定する。送り先が KYOTANGO のリポジトリでなければ何もしない。
- GitHub 側の変更とこのパソコンの変更が同じ場所でぶつかったときは、何も公開せずに止まる（このパソコンの変更はコミットとして残る）。
- 公開すると1分ほどで GitHub Pages に反映される。

### 開いている先生用ページの自動切り替え
- 先生用ページは5分ごとに公開中の版（`APP_VERSION`）を確かめる。新しい版があれば、生徒・副担当が誰もつながっていないときはすぐに再読み込みして切り替わる。授業中は案内を出し、全員が抜けたところで切り替わる（授業の途中で勝手に切れることはない）。
- 切り替えたときは入退室の記録に「記録終了：新しい版に切り替え」が残り、続けて新しい入室が記録される。
- 版を書き換えずに公開した場合は切り替わらない（`publish` を使えば自動で書き換わる）。

## 運用メモ
- クラスコードはブラウザに保存され、毎回同じ（「コードを変更」で作り直し）。授業ごとに変えるとより安全。
- 生徒用URLはZoomのチャットなどクラス内だけで伝える。
- 先生のページを再読み込みしても、生徒は数秒で自動再接続する。
- 先生用ページは前面に出しておく（裏に隠すとブラウザが判定を間引く）。
- 生徒には、共有前に授業に関係のないタブ・アプリ・通知を閉じるよう伝える。
- スプレッドシートの共有設定は「自分のみ」にしておく。

## 動作テスト
先生用ページでコピーした生徒用URLの末尾に `&demo=1` を付けると、画面共有の代わりにダミー映像（1分入力・1分停止を繰り返す）を送れる。
別のタブ・シークレットウィンドウで複数開けば、一人で動作確認できる。

## 注意
- 「変化なし」は画面が動いていないという意味。読んでいる・考えている場合もあるので目安として使う。
- 学校のネットワークで外部への通信（WebRTC）が制限されていると、つながらない場合がある。
- 生徒・保護者へ「授業中のみ、先生が画面を見る（録画なし）」ことを事前に説明しておくと安心。
