# 画面モニター（遠隔授業用）

生徒（Chromebook）の画面を先生が一覧でリアルタイムに見るためのWebアプリ。
手が止まっている生徒を自動で色分けし、生徒は「🙋 困っています」ボタンで先生に知らせられる。

## ファイル
- `index.html` … 生徒用（先生から送られたURLで開き、名前を入れて画面共有）
- `teacher.html` … 先生用（一覧・拡大・メッセージ送信）。先生用URL（`?co=…&k=…&t=…`）で開くと副担当として参加

## 仕組み
- WebRTC（PeerJS 1.5.4）で生徒→先生へ画面を直接ライブ配信。遅延は1秒未満。
- 接続の仲介はPeerJSの無料公開サーバー（0.peerjs.com）。映像はサーバーに保存されず、録画もしない。
- 一覧表示中は軽量画質（横640px・約4fps・250kbps）。タイルをクリックして拡大した生徒だけ高画質（約10fps・2Mbps）に切り替わる。
  40人で先生側の受信はおよそ10Mbps。
- 先生側で1秒ごとに各画面の変化を調べ、変化がない時間で色分けする（初期値：2分で黄、5分で赤）。
  画面下端（Chromebookの時計・シェルフ）は判定から除外。

## 授業での使い方
1. 先生：`teacher.html` を開き「生徒用URLをコピー」→ Zoomのチャットで送る
2. 生徒：URLを開き、名前を入力 →「画面共有をはじめる」→「画面全体」を選んで共有
3. 生徒はそのタブを閉じずに、課題のタブへ切り替えて作業
4. 先生：要対応順に並ぶので、上から確認。クリックで拡大＋メッセージのやり取り

## メッセージ機能
- 生徒→先生：生徒ページの「💬 先生とのメッセージ」欄から送信。先生側はタイルに「💬 未読数」が出て音が鳴り、一覧の上位に並ぶ。
- 先生→生徒：タイルをクリックした拡大画面の右側で、その生徒との履歴を見ながら返信（定型文ボタンあり）。
- 先生→全員：上部の「📢 全員に送信」で、つながっている生徒全員に一斉送信。
- 先生側の履歴は先生のブラウザに保存（クラスコードごと。「コードを変更」で消去）。生徒側の履歴はタブを閉じると消える（共用端末対策）。サーバーには残らない。
- 相手とつながっていないときは送信できない（その旨を表示）。

## 複数の先生で見る（主担当1名＋副担当最大4名）
1. 主担当：「👥 先生」→「先生用URLをコピー」→ 一緒に見る先生に送る（最初に1回だけ。**生徒には絶対に送らない**）
2. 副担当：先生用URLを開いて表示名を入れるだけで参加（承認の操作は不要）
3. **主担当がページを開くと**、待っていた副担当と生徒が自動で始まる。主担当が入るまでは「主担当の先生の入室を待っています」と表示される

- 主担当・副担当とも画面とボタンは同じ。主担当だけの操作（コードを変更・先生用URLを作り直す・記録設定・先生を外す）は、副担当の画面では灰色で押せない。
- 副担当も「生徒用URLをコピー」「📢 全員に送信」「👥 先生（参加中の先生一覧）」を使える。
- 先生用URLには先生専用の合言葉（`t`）が入っている。漏れたときは主担当が「先生用URLを作り直す」→ 古いURLは使えなくなり、参加中の副担当もいったん外れる（新しいURLを送り直す）。
- 特定の先生だけ外すときは「👥 先生」→「外す」（先生用URLを作り直すまで、その先生は再参加できない）。
- 生徒のメッセージは全先生に届く。誰かが返信すると、ほかの先生の画面にも「先生（田中）」のように表示される。後から入った先生にもそれまでのやり取りが共有される。
- 生徒は副担当にも本人確認（署名の検証）をしてから画面を送る。副担当の鍵の指紋は、主担当から本人確認済みの接続で届く。
- スプレッドシート記録は主担当のパソコンからだけ行う（副担当の返信も主担当経由で記録される）。
- 生徒側の送信量は先生の人数分になる（一覧用の軽い画質で 1人あたり約0.25Mbps × 先生の数）。

## スプレッドシート記録の準備（初回だけ・約5分）
先生用ページから、やり取りをGoogleスプレッドシートへ自動で追記できる。
記録されるのは「生徒→先生」「先生→生徒」「先生→全員」「🙋ボタン」。列は 日時／クラスコード／生徒名／送信者／内容。

1. Googleドライブで新しいスプレッドシートを作る（名前例：画面モニター記録）
2. メニュー「拡張機能」→「Apps Script」を開き、最初からあるコードを消して `gas/Code.gs` の中身を貼り付けて保存
3. 上部の関数選択で `setup` を選び「実行」→ 権限の確認が出たら自分のアカウントで許可
   （「このアプリは確認されていません」と出たら「詳細」→「（安全ではないページ）に移動」）
4. 下の実行ログに出る **合言葉** を控える（あとでスプレッドシートのメニュー「画面モニター」→「合言葉を表示」でも見られる）
5. 右上「デプロイ」→「新しいデプロイ」→ 歯車で「ウェブアプリ」を選ぶ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   →「デプロイ」→ 表示された **ウェブアプリURL**（…/exec）をコピー
6. 先生用ページの「📝 記録設定」に URL と合言葉を入れ「接続テスト」→ 成功したら「保存して閉じる」

- ヘッダーの「記録：✅ 保存中」が出ていれば記録されている。通信が切れても送信待ちとしてためておき、つながり次第自動で送る（重複はしない）。
- URLと合言葉は先生のブラウザにだけ保存される（公開されるファイルには含まれない）。生徒のページからは記録しない。
- `Code.gs` を書き換えたときは「デプロイ」→「デプロイを管理」→ 編集 → バージョン「新バージョン」で更新（URLは変わらない）。
- 生徒の発言を保存するので、学校の個人情報の取り扱いルールを確認しておくこと。

## セキュリティ対策
- **先生のなりすまし防止**：先生用ページは初回に署名用の鍵（ECDSA P-256）を作り、秘密鍵を取り出し不可の形でそのブラウザ（IndexedDB）に保存する。
  生徒用URLの `k` は公開鍵の指紋。生徒ページは接続のたびに乱数を送り、先生の署名を確かめてから名前・画面を送る。
  URLやクラスコードを知っていても、先生のブラウザがなければ画面は受け取れない。
- **名前を仲介サーバーに渡さない**：名前などは本人確認後、暗号化された直接接続で送る。
- **改ざん対策**：PeerJSはSRI（integrity属性）付きで読み込む。
- **いたずら対策**：生徒1人あたりメッセージは30秒に5件、🙋は1分に10回まで。接続は最大80人。生徒ページ側も2秒に1件まで。
- 先生の鍵はそのブラウザ専用。**別のパソコン・別のブラウザ・シークレットウィンドウで先生用ページを開くと生徒用URLが変わる**（URLを送り直す）。
  ブラウザのサイトデータを消した場合も同様。
- 第三者が授業前に先生の接続IDを先に取ると、先生のページが「使用中」になる（画面は漏れない）。続く場合は「コードを変更」。

## 運用メモ
- クラスコードはブラウザに保存され、毎回同じ（「コードを変更」で作り直し）。授業ごとに変えるとより安全。
- 生徒用URLはZoomのチャットなどクラス内だけで伝える。
- 先生のページを再読み込みしても、生徒は数秒で自動再接続する。
- 先生用ページは前面に出しておく（裏に隠すとブラウザが判定を間引く）。
- 生徒には、共有前に授業に関係のないタブ・アプリ・通知を閉じるよう伝える。
- スプレッドシートの共有設定は「自分のみ」にしておく。

## 動作テスト
先生用ページでコピーした生徒用URLの末尾に `&demo=1` を付けると、画面共有の代わりにダミー映像（1分入力・1分停止を繰り返す）を送れる。
別のタブ・シークレットウィンドウで複数開けば、一人で動作確認できる。

## 注意
- 「変化なし」は画面が動いていないという意味。読んでいる・考えている場合もあるので目安として使う。
- 学校のネットワークで外部への通信（WebRTC）が制限されていると、つながらない場合がある。
- 生徒・保護者へ「授業中のみ、先生が画面を見る（録画なし）」ことを事前に説明しておくと安心。
